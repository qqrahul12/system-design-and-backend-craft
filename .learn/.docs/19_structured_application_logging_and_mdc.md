# 📜 Structured Application Logging & Context Tracking (MDC)

In a distributed microservices architecture, simple `System.out.println` statements are completely inadequate. When a user request traverses 5 different microservices, you need a way to trace that exact request through all logs. 

## 1. The Problems with Standard `println` Logging

1. **No Concurrency Context:** In Spring Boot (which handles hundreds of concurrent requests), standard prints don't tell you *which* thread or user action caused the log.
2. **No Tracing:** If `movie-booking-service` calls `payment-service`, and the payment fails, how do you correlate the booking log with the payment log?
3. **Unstructured Data:** Plain text logs are hard to parse. When you have millions of logs, you need them in JSON format so tools like Elasticsearch, Datadog, or OpenObserve can index and search them.

---

## 2. The Solution: SLF4J, Logback, and MDC

### A. The Logger Abstraction (SLF4J)
Instead of tying your code directly to a logging implementation, you use SLF4J (Simple Logging Facade for Java). Lombok provides the handy `@Slf4j` annotation, which injects a `log` variable into your class.

```java
import lombok.extern.slf4j.Slf4j;

@Slf4j
public class PaymentService {
    public void process() {
        log.info("Processing payment");
        log.error("Failed to process payment"); // Automatically includes thread names, timestamps, and log levels
    }
}
```

### B. Mapped Diagnostic Context (MDC)
MDC is a thread-local map provided by logging frameworks (like Logback). It allows you to inject contextual data (like a `traceId` or `userId`) into **every single log** generated by that thread, without passing those variables through every method signature.

**Example MDC Setup (Usually done in a Spring Interceptor/Filter):**
```java
import org.slf4j.MDC;

public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) {
    String traceId = request.getHeader("X-Trace-Id");
    if (traceId == null) traceId = UUID.randomUUID().toString();
    
    // Put context in MDC
    MDC.put("traceId", traceId);
    MDC.put("userId", request.getHeader("X-User-Id"));
    
    try {
        // Every log inside the chain will now have traceId and userId attached!
        chain.doFilter(request, response);
    } finally {
        // CRITICAL: Always clear MDC in a finally block because Tomcat reuses threads!
        MDC.clear();
    }
}
```

### C. Structured JSON Logging
By configuring `logback-spring.xml`, you can output logs directly as JSON.

```json
{
  "timestamp": "2026-08-22T21:00:00.000Z",
  "level": "INFO",
  "thread": "http-nio-8080-exec-1",
  "logger": "com.booking.service.PaymentGatewayClient",
  "message": "Making actual HTTP call to payment-service for bookingId: B-123",
  "traceId": "abc-123-xyz",
  "userId": "user_99"
}
```

## 3. Real-World Architecture
1. **App generates JSON logs** (with MDC trace IDs).
2. **Sidecar / Agent** (like Filebeat, Vector, or Promtail) tails the log files.
3. **Log Aggregator** (Elasticsearch, OpenObserve, Datadog) ingests the logs.
4. **Developer** searches for `traceId: "abc-123-xyz"` and sees the exact flow across `movie-booking-service` AND `payment-service` in one unified dashboard!
